STEP 23 — INTEGRATING THE THEME PROVIDER
When rendering components such as Button, Input, or Typography inside Storybook, styled-components attempted to access theme.colors but failed with:

text
TypeError: Cannot read properties of undefined (reading 'colors')
Root Cause:
Storybook stories were rendered without being wrapped by the ThemeProvider.

STEP 24 — FIX WITH GLOBAL DECORATOR
The fix was implemented via a decorator in .storybook/preview.js, which wraps all stories with the same ThemeProvider and GlobalStyle used in the Next.js app.

Final code:
javascript
// .storybook/preview.js

import { ThemeProvider } from 'styled-components';
import { theme, GlobalStyle } from '../src/styles/theme';

const preview = {
  decorators: [
    (Story) => (
      <ThemeProvider theme={theme}>
        <GlobalStyle />
        <Story />
      </ThemeProvider>
    ),
  ],
  parameters: {
    controls: { expanded: true },
    actions: { argTypesRegex: '^on[A-Z].*' },
  },
};

export default preview;
✅ Now all components properly receive the theme context.

STEP 26 — BUILDING PRODUCTION-GRADE STORIES
After confirming proper styling, professional stories were implemented for all key UI components.

Each story uses args + controls for live prop editing.

Example: Button.stories.js
js
import Button from './Button'

export default {
  title: 'UI/Button',
  component: Button,
  args: {
    children: 'Button',
    variant: 'solid',
    size: 'md',
    disabled: false,
  },
  argTypes: {
    variant: { control: 'select', options: ['solid', 'outline', 'ghost'] },
    size: { control: 'select', options: ['sm', 'md', 'lg'] },
  },
}

export const Solid = {}
export const Outline = { args: { variant: 'outline' } }
export const Disabled = { args: { disabled: true } }
This setup allowed developers to:

Edit props dynamically from the Storybook UI
Preview size, variant, and state changes instantly
Ensure visual consistency across all components

STEP 28 — ADDING DECORATOR FOR PRODUCT CARD
When testing the ProductCard component, the Storybook view appeared too large, filling the entire canvas.

This was because ProductCard is designed to sit inside a grid container (ProductList), not as a full-page component.

Fix:
A container decorator was added to simulate the layout constraint.


نمایش کد


// src/components/product/ProductCard/ProductCard.stories.js

import ProductCard from './ProductCard'

export default {
  title: 'Product/ProductCard',
  component: ProductCard,
  decorators: [
    (Story) => (
      <div style={{ maxWidth: '320px', margin: '0 auto' }}>
        <Story />
      </div>
    ),
  ],
}

const mockProduct = {
  id: 1,
  title: 'MacBook Pro M3',
  price: '120000000',
  image: '/images/headphones.webp',
}

export const Default = {
  args: { product: mockProduct },
}
Result:

✅ The card displayed in realistic dimensions

✅ Correct bottom spacing and hover effects

✅ Product image rendering properly inside grid constraints
